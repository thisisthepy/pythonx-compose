Compose, in Python.Compose 를, 파이썬으로.

Build Compose Multiplatform UIs in Python. A Python declarative UI framework: Compose's own widgets with their own parameters, spelled the way Python spells things.파이썬으로 Compose Multiplatform UI 를 만듭니다. 파이썬 선언형 UI 프레임워크로, Compose 의 위젯과 매개변수를 그대로 쓰되 파이썬다운 이름으로 씁니다.

The idea아이디어

Same widgets. Python names.같은 위젯, 파이썬 이름.

Nothing is reimplemented and nothing is invented. Every parameter on the right is a Compose parameter on the left, renamed by one rule: camelCase becomes snake_case.

다시 구현하는 것도, 새로 지어내는 것도 없습니다. 오른쪽의 모든 매개변수는 왼쪽 Compose 의 매개변수이고, 규칙 하나로 이름만 바뀝니다: camelCase 가 snake_case 가 됩니다.

Kotlin · androidx.compose.material3

Button(
    onClick = { send() },
    modifier = Modifier.padding(16.dp),
    enabled = true,
) {
    Text("Send")
}
→

Python · pythonx.compose.material3

Button(
    on_click=lambda: send(),
    modifier=Modifier.padding(16),
    enabled=True,
    content=lambda: Text("Send"),
)

These names resolve today, by one rule, inside an app that embeds the binder. Per-widget render proofs through this package are still pending; the status page says what is done and what is not.

이 이름들은 바인더를 임베딩한 앱 안에서 지금 규칙 하나로 해석됩니다. 이 패키지를 거친 위젯별 렌더링 증거는 아직 대기 중이며, 무엇이 되고 무엇이 안 되는지는 현황 페이지에 있습니다.

The original API원래 API 그대로

Compose 자신의 매개변수를 snake_case 로. Kotlin 에 없는 편의 매개변수는 만들지 않습니다.

Extensions are methods확장 함수는 메서드

A Kotlin extension function is a method on its receiver, so chains read as they do in Kotlin, fill_max_width() included.

Kotlin 확장 함수는 수신 객체의 메서드가 되어, 체인이 Kotlin 에서처럼 읽힙니다. fill_max_width() 도 마찬가지입니다.

What it is not이것이 아닌 것

  • Not the binder: embedding CPython and the FFI belong to python-multiplatform.바인더가 아닙니다: CPython 임베딩과 FFI 는 python-multiplatform 의 몫입니다.
  • Not a reimplementation of Compose, and not a new widget set.Compose 의 재구현도, 새 위젯 세트도 아닙니다.
  • Not runtime reflection: bindings are produced at build time, because native images and Kotlin/Native have none.런타임 리플렉션이 아닙니다: 네이티브 이미지와 Kotlin/Native 에는 리플렉션이 없으므로 바인딩은 빌드 타임에 만듭니다.
