Modifier chainsModifier 체인

Kotlin extension functions, as Python methods.Kotlin 확장 함수를 파이썬 메서드로.

partial부분

Chains, snake_case method names, overload dispatch and Dp as a number are implemented and pass against the binder's adaptation layer (python-multiplatform ba4c6f49 or later). The partial piece is where a chain starts against real Compose — see the empty Modifier below.

체인, snake_case 메서드 이름, 오버로드 디스패치, 숫자로 쓰는 Dp 는 구현되어 있고 바인더의 적응 계층(python-multiplatform ba4c6f49 이후)에서 통과합니다. 부분적인 것은 실제 Compose 에서 체인이 시작되는 지점입니다 — 아래 빈 Modifier 를 보세요.

Chaining체이닝

from pythonx.compose.ui import Modifier

m = Modifier.padding(16).size(24).fill_max_width()

Each link returns a new receiver; nothing is mutated. Method names are snake_case (fill_max_width reaches fillMaxWidth): the naming rule is registered as the binder's member resolver, while the binder's proxy class itself keeps Kotlin names in dir(). A name that is not bound raises AttributeError naming the type it looked on.

각 단계는 새 수신 객체를 돌려주며, 아무것도 변경하지 않습니다. 메서드 이름은 snake_case 입니다(fill_max_width 가 fillMaxWidth 에 닿음): 이름 규칙이 바인더의 멤버 리졸버로 등록되어 있고, 바인더의 프록시 클래스 자체는 dir() 에 Kotlin 이름을 유지합니다. 바인딩되지 않은 이름은 어느 타입에서 찾았는지 밝히는 AttributeError 를 냅니다.

Overloads오버로드

Compose declares several padding functions. A call picks one by keyword names, then argument count, then declared type; if none matches, the error lists the candidates.

Compose 는 padding 함수를 여러 개 선언합니다. 호출은 키워드 이름, 인자 개수, 선언 타입 순으로 하나를 고르며, 맞는 것이 없으면 후보를 나열한 오류를 냅니다.

m.padding(16)                          # all sides
m.padding(horizontal=8, vertical=4)    # selected by keyword names
m.padding(1, 2, 3, 4)                  # selected by argument count
m.padding__Dp(16)                      # explicit overload: no dispatch

Keywords: method or module function키워드: 메서드와 모듈 함수

The member resolver maps names, not keywords, so a keyword argument to a method is still Kotlin's own. The same extension called as a module function takes snake_case keywords, and inspect.signature shows them:

멤버 리졸버는 키워드가 아니라 이름을 대응시키므로, 메서드의 키워드 인자는 아직 Kotlin 그대로입니다. 같은 확장 함수를 모듈 함수로 부르면 snake_case 키워드를 받고, inspect.signature 도 그 이름을 보여 줍니다:

import inspect
import pythonx.compose.layout as layout

values = layout.padding_values_of(8)
m.padding(paddingValues=values)               # method: Kotlin keyword
layout.padding(m, padding_values=values)      # module function: snake_case keyword

inspect.signature(layout.padding__PaddingValues)
# (receiver, padding_values)

Numbers and value classes숫자와 값 클래스

Dp takes a raw number because the manifest allows it; a plain Float parameter is just a float; a packed value class such as TextUnit refuses a raw number and says why.

Dp 는 매니페스트가 허용하므로 숫자를 받습니다. 평범한 Float 매개변수는 그냥 float 이고, TextUnit 같은 묶인 값 클래스는 숫자를 거절하며 이유를 밝힙니다.

m.padding(16)                  # Dp from a number
m.z_index(1.5)                 # a plain Float
m.padding_from_baseline(16)    # TypeError: TextUnit would be reinterpreted

The empty Modifier빈 Modifier

In Kotlin, Modifier as an expression is an object, and bindings are functions — so there is no bound name for the empty modifier a chain starts from. pythonx/compose/ui/modifier.py is the seam: an application registers a one-line Kotlin factory.

Kotlin 에서 식으로 쓰인 Modifier 는 객체이고 바인딩은 함수이므로, 체인이 시작하는 빈 모디파이어에는 바인딩된 이름이 없습니다. pythonx/compose/ui/modifier.py 가 그 접점이며, 앱이 한 줄짜리 Kotlin 팩토리를 등록합니다.

// in the application's Kotlin
fun emptyModifier(): Modifier = Modifier
import pythonx.compose.ui.modifier as seam

seam.install("com.example.emptyModifier")   # then Modifier.padding(16) works

Without it, Modifier.padding(16) raises a TypeError naming register_empty. A Modifier instance Kotlin hands out chains without it.

이것이 없으면 Modifier.padding(16) 은 register_empty 를 밝히는 TypeError 를 냅니다. Kotlin 이 건네준 Modifier 인스턴스는 이것 없이도 체이닝됩니다.
