Writing composables컴포저블 작성하기

Screens are functions; widgets are Compose's own.화면은 함수이고, 위젯은 Compose 의 것입니다.

partial부분

pythonx.compose.material3 re-exports androidx.compose.material3 by the one naming rule: composables keep their Kotlin names and take snake_case keywords (on_click=), with no per-widget file. The widgets have been rendered from Python in python-multiplatform's own tests (Text, Button, Card, ListItem, Badge, MaterialTheme, IconButton, Checkbox, Switch, TextField); a render proof per widget through this package is still pending (#9).

pythonx.compose.material3 는 이름 규칙 하나로 androidx.compose.material3 를 재노출합니다: 컴포저블은 Kotlin 이름을 유지하고 snake_case 키워드(on_click=)를 받으며, 위젯별 파일은 없습니다. 이 위젯들은 python-multiplatform 자체 테스트에서 파이썬으로 렌더링되었습니다 (Text, Button, Card, ListItem, Badge, MaterialTheme, IconButton, Checkbox, Switch, TextField). 이 패키지를 거친 위젯별 렌더링 증거는 아직 대기 중입니다(#9).

Write a screen화면 하나 쓰기

from pythonx.compose.runtime import Composable
from pythonx.compose.material3 import Text, Card

@Composable
def Profile(name: str):
    Card(content=lambda: Text(f"Hello, {name}"))

A screen is a plain function. @Composable marks it; it does not wrap it. Content slots take a lambda.

화면은 평범한 함수입니다. @Composable 은 표시만 하고 감싸지 않습니다. content 슬롯은 람다를 받습니다.

Column, Row and Spacer are declared in Kotlin's layout package, and the notebook imports them from material3. Both work, and both give the same object: the manifest's [aliases] section lends them to material3:

Column, Row, Spacer 는 Kotlin 의 layout 패키지에 선언되어 있고, 노트북은 이들을 material3 에서 import 합니다. 둘 다 되며 같은 객체를 줍니다. 매니페스트의 [aliases] 섹션이 이들을 material3 에 빌려줍니다:

from pythonx.compose.material3 import Column, Row, Spacer   # as the notebook writes
from pythonx.compose.layout import Column                   # Kotlin's home; same object

Declare the app and keep state앱 선언과 상태

from pythonx.compose.runtime import app, mutable_state_of
from pythonx.compose.material3 import Text, Button

count = mutable_state_of(0)

@app
def Main():
    Button(on_click=lambda: setattr(count, "value", count.value + 1),
           content=lambda: Text(f"Clicked {count.value}"))

@app declares the screen the host draws and returns the function unchanged. Declaring it again, for example in a notebook cell, replaces the screen; there is no update call. mutable_state_of(initial) is Compose's own mutableStateOf, read and written through .value; there is no second name for it. The host is configured once with PythonAppView(module = "pythonx.compose.runtime", attribute = "app_root").

@app 은 호스트가 그리는 화면을 선언하고 함수를 그대로 돌려줍니다. 노트북 셀 등에서 다시 선언하면 화면이 바뀌며, 갱신 호출은 없습니다. mutable_state_of(initial) 는 Compose 의 mutableStateOf 그대로이며 .value 로 읽고 씁니다. 다른 이름은 두지 않습니다. 호스트는 PythonAppView(module = "pythonx.compose.runtime", attribute = "app_root") 로 한 번만 설정합니다.

Status: partial. The binder path, which creates the state through Compose's mutableStateOf, is tested against a fake host shaped after python-multiplatform #38; against real Compose, python-multiplatform's notebook E2E passes. Numbers and strings round-trip: mutable_state_of(0) and count.value += 1 work (python-multiplatform #69).

상태: 부분. Compose 의 mutableStateOf 로 상태를 만드는 바인더 경로는 python-multiplatform #38 모양의 가짜 호스트로 테스트되었으며, 실제 Compose 에서는 python-multiplatform 의 노트북 E2E 가 통과합니다. 숫자와 문자열은 왕복됩니다: mutable_state_of(0) 과 count.value += 1 이 동작합니다(python-multiplatform #69).

A text field텍스트 필드

from pythonx.compose.material3 import TextField, Text
from pythonx.compose.foundation.text.input import remember_text_field_state

field = remember_text_field_state("")          # inside a composable
TextField(state=field, label=lambda scope: Text("Message"))
field.text                                      # the committed text, read when you need it (say, on submit)

# outside composition, such as a notebook cell
from pythonx.compose.foundation.text.input import TextFieldState
draft = TextFieldState("hi")
draft.set_text_and_place_cursor_at_end("hello")
draft.clear_text()

Compose keeps the text and the input method's composing region, so nothing is sent to Python per keystroke; you read field.text on demand. Keep this state apart from state you stream output into, such as messages = state(""). The notebook's TextField(text_state=…, padding=8) has no Kotlin counterpart and is written TextField(state=…, modifier=Modifier.padding(8)). Status: partial. Tested against a fake host; the input-method proof is python-multiplatform's end-to-end test (#26).

Compose 가 텍스트와 입력기의 조합 영역을 보관하므로 키 입력마다 파이썬으로 보내지는 것이 없고, 필요할 때 field.text 를 읽습니다. 이 상태는 출력을 흘려 넣는 상태(예: messages = state(""))와 분리해 두세요. 노트북의 TextField(text_state=…, padding=8) 은 Kotlin 에 대응이 없으며 TextField(state=…, modifier=Modifier.padding(8)) 로 씁니다. 상태: 부분. 가짜 호스트로 테스트되었으며, 입력기 증거는 python-multiplatform 의 종단 간 테스트(#26)입니다.

The notebook's signatures are examples. The surface follows Compose:

노트북의 시그니처는 예시입니다. 실제 표면은 Compose 를 따릅니다:

Notebook노트북Compose parameterCompose 매개변수Python

fontSize is a TextUnit, which packs several fields into one value, so font_size refuses a raw number such as 30.

fontSize 는 여러 필드를 한 값에 담는 TextUnit 이므로, font_size 는 30 같은 숫자를 거절합니다.

노트북의 편의 표기 몇 가지는 Kotlin 에 그런 것이 없으므로 다르게 씁니다:

Notebook노트북PythonWhy이유

What does not work yet아직 안 되는 것

  • The colour-scheme factories cannot be called yet: they take 36 colour parameters. DefaultIcons is Icons.Default, an icon is a value (an ImageVector to a type checker) read without parentheses: Icon(DefaultIcons.Add, content_description=None), not the notebook's DefaultIcons.Add(). It is tested here against a fake host only; the real draw is in python-multiplatform's render test.색 스킴 팩토리는 색 매개변수를 36 개 받아 아직 호출할 수 없습니다. DefaultIcons 는 Icons.Default 이고, 아이콘은 괄호 없이 읽는 값(타입 검사기에는 ImageVector)입니다. 노트북의 DefaultIcons.Add() 가 아니라 Icon(DefaultIcons.Add, content_description=None). 여기서는 가짜 호스트로만 테스트되며, 실제 그리기는 python-multiplatform 의 렌더 테스트에 있습니다.
  • TextField(state=…) is wired and tested against a fake host only; that the input method's composing sequence survives, with no Python callback per keystroke, is proved in python-multiplatform's end-to-end test (#26).TextField(state=…) 는 가짜 호스트로만 테스트되었습니다. 입력기의 조합 입력이 키 입력마다 파이썬 콜백 없이 유지되는지는 python-multiplatform 의 종단 간 테스트(#26)에서 증명합니다.
  • remember_saveable and the coroutine scopes the notebook imports are planned.노트북이 import 하는 remember_saveable, 코루틴 스코프는 계획 단계입니다.
