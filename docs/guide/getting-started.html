Getting started시작하기

From clone to first call클론부터 첫 호출까지

Five minutes, honest about what runs.5 분, 동작하는 범위를 솔직하게.

pythonx-compose is an alpha: 0.1.0a3 is on PyPI. As a pre-release it installs with uv add --prerelease allow pythonx-compose; with ppp it is ppp core add "pythonx-compose==0.1.0a3", with tcl tcl install pythonx-compose. It needs Python 3.11 or later. This page shows how to get the source, run the tests, and what you can call today.

pythonx-compose 는 알파 단계이며 0.1.0a3 가 PyPI 에 있습니다. 프리릴리스이므로 uv add --prerelease allow pythonx-compose 로 설치하며, ppp 로는 ppp core add "pythonx-compose==0.1.0a3", tcl 로는 tcl install pythonx-compose 입니다. 파이썬 3.11 이상이 필요합니다. 이 페이지는 소스를 받고, 테스트를 돌리고, 지금 호출할 수 있는 것을 보여줍니다.

1. Get the source1. 소스 받기

git clone https://github.com/thisisthepy/pythonx-compose
cd pythonx-compose

2. Run the tests2. 테스트 실행

uv run --with pytest --with mypy pytest tests -q

Expect 163 passed, 141 skipped. One skipped test reads the maintainer's UI.ipynb, which a clone does not have; mypy type-checks the stubs. The other skipped tests drive the binder's adaptation layer and need a python-multiplatform checkout beside this one, or:

163 passed, 141 skipped 가 정상입니다. 건너뛴 테스트 하나는 클론에는 없는 메인테이너의 UI.ipynb 를 읽으며, mypy 는 스텁을 타입 검사합니다. 나머지 건너뛴 테스트는 바인더의 적응 계층을 구동하며, 옆에 python-multiplatform 체크아웃이 있거나 다음이 필요합니다:

PYTHONMULTIPLATFORM_HOME=/path/to/python-multiplatform uv run --with pytest --with mypy pytest tests -q

With a current one (6cf658d8 or later) 301 pass and 3 skip on CI (UI.ipynb, the downloaded stubs artefact, and optional pythonx-concurrent); an older one skips 5 that call a snake_case method on a proxy the binder returned. That is expected and recorded.

최신 체크아웃(6cf658d8 이후)이면 CI 에서 301 개가 통과하고 3 개(UI.ipynb, 내려받은 스텁 아티팩트, 선택적인 pythonx-concurrent)를 건너뛰며, 오래된 체크아웃은 바인더가 돌려준 proxy 의 snake_case 메서드를 부르는 5 개를 건너뜁니다. 예상된 상태이며 기록되어 있습니다.

3. What you can call today3. 지금 호출할 수 있는 것

From the repository root:

저장소 루트에서:

from pythonx.compose.runtime import Composable

@Composable                 # identity: the function stays a plain function
def Screen():
    """A screen."""
    return "drawn"

assert Screen() == "drawn" and Screen.__name__ == "Screen"
import tomllib

with open("pythonx/compose/pythonx-map.toml", "rb") as f:
    manifest = tomllib.load(f)

manifest["modules"]["pythonx.compose.layout"]
# 'androidx.compose.foundation.layout'

The naming rule itself needs no binder either:

이름 규칙 자체도 바인더 없이 동작합니다:

from pythonx.compose._reexport import python_name

python_name("fillMaxWidth")   # 'fill_max_width'
python_name("toURLString")    # 'to_url_string'
python_name("padding__Dp")    # 'padding__Dp'  (an explicit overload keeps its suffix)
python_name("Modifier")       # 'Modifier'     (upper-case names keep their spelling)

Every mapped module imports on its own. Reading a Compose name from it needs the binder, which the Kotlin host installs; outside an app the error says so:

대응된 모듈은 모두 그 자체로 import 됩니다. 그 모듈에서 Compose 이름을 읽으려면 Kotlin 호스트가 설치하는 바인더가 필요하며, 앱 밖에서는 오류가 그 사실을 알려 줍니다:

import pythonx.compose.material3 as material3   # fine: a real file on disk

material3.Text
# RuntimeError: the python-multiplatform binding layer is not installed:
# the Kotlin host must run PythonxAdapter.install() before pythonx.compose
# can resolve a Kotlin declaration

4. What you write in an app4. 앱 안에서 쓰는 코드

Inside an app whose Kotlin host has installed the binder, a screen looks like this: every name and parameter is Compose's own, spelled by the one rule:

Kotlin 호스트가 바인더를 설치한 앱 안에서는, 화면이 이렇게 됩니다. 모든 이름과 매개변수는 Compose 자신의 것이며, 규칙 하나로 표기됩니다:

from pythonx.compose.runtime import Composable
from pythonx.compose.material3 import Text, Button, Column   # Column also from layout
from pythonx.compose.layout import Arrangement
from pythonx.compose.ui import Alignment, Modifier

@Composable
def Practice():
    Column(
        modifier=Modifier.padding(16).fill_max_width(),
        vertical_arrangement=Arrangement.spaced_by(8),
        horizontal_alignment=Alignment.CenterHorizontally,   # read, not called
        content=lambda: (
            Text("Hello"),
            Button(on_click=lambda: None, content=lambda: Text("Press")),
        ),
    )

Two things to know. A chain that starts from the class, Modifier.padding(16), or passing Modifier itself evaluates Modifier.Companion out of the box (#134, #138); see Modifiers. And a declared app root (@app) replaces the screen when redefined in a cell (#11); see Composables.

알아 둘 것이 두 가지 있습니다. 클래스에서 시작하는 체인 Modifier.padding(16) 이나 Modifier 자체를 인자로 넘기는 표기는 기본 등록된 Modifier.Companion 을 평가합니다(#134, #138). 모디파이어를 보세요. 그리고 선언형 앱 루트(@app)는 셀에서 화면을 다시 정의하면 그대로 교체합니다(#11). 컴포저블을 보세요.

5. Host it in a desktop app5. 데스크톱 앱에 띄우기

This recipe needs python-multiplatform 3.15.0-alpha03 on Maven Central: org.thisisthepy:python-multiplatform, org.thisisthepy:python-multiplatform-compose and the Gradle plugin org.thisisthepy.python.multiplatform.bindings. It follows the host of python-multiplatform's notebook E2E, which passes all 20 UI.ipynb scenarios; this exact project has not yet been run against the published artefacts.

이 레시피에는 Maven Central 의 python-multiplatform 3.15.0-alpha03 이 필요합니다: org.thisisthepy:python-multiplatform, org.thisisthepy:python-multiplatform-compose, Gradle 플러그인 org.thisisthepy.python.multiplatform.bindings. python-multiplatform 노트북 E2E 의 호스트를 그대로 따르며, 그 E2E 는 UI.ipynb 의 20 개 시나리오를 모두 통과합니다. 이 프로젝트 자체를 배포된 아티팩트로 돌려 본 기록은 아직 없습니다.

The app is a Kotlin Multiplatform project with one desktop target, and a uv project for the Python side:

앱은 데스크톱 타깃 하나를 가진 Kotlin Multiplatform 프로젝트이고, 파이썬 쪽은 uv 프로젝트입니다:

The Python side: install the package with uv and write the screen as the notebook does, as module main with a root App:

파이썬 쪽: uv 로 패키지를 설치하고, 노트북처럼 화면을 main 모듈의 루트 App 으로 씁니다:

mkdir python && cd python
uv init --bare
uv add --prerelease allow pythonx-compose
# python/main.py
from pythonx.compose.runtime import Composable, app, remember_saveable
from pythonx.compose.material3 import Text

@app
@Composable
def App():
    App.messages = messages = remember_saveable("Hello from Python")
    Text(messages.getValue())

The Gradle side. Every repository is a standard one: the Compose fork org.thisisthepy.compose and python-multiplatform are both on Maven Central. Build with Kotlin 2.4.20-Beta2, the version python-multiplatform is compiled with.

The Kotlin main starts the interpreter, installs the binder, imports main and draws its root with PythonAppView, the one host line pythonx-compose is configured with:

Kotlin main 은 인터프리터를 시작하고, 바인더를 설치하고, main 을 import 한 뒤 그 루트를 PythonAppView 로 그립니다. pythonx-compose 가 호스트에 요구하는 설정은 이 한 줄입니다:

// src/desktopMain/kotlin/app/Main.kt
package app

import androidx.compose.ui.window.Window
import androidx.compose.ui.window.application
import python.multiplatform.compose.PythonAppView
import python.multiplatform.ffi.Python3
import python.multiplatform.ffi.pythonx.PythonxAdapter
import python.multiplatform.ffi.upcall.PythonProxySource
import python.multiplatform.ffi.upcall.UpcallBootstrap
import python.multiplatform.generated.FunctionTable
import python.multiplatform.generated.artifacts.ArtifactTable
import python.multiplatform.reflection.UpcallTable

fun main() {
    Python3.initialize()
    // The binder: the generated tables, the upcall entry points, the proxies, androidx.compose.*.
    UpcallTable.install(FunctionTable.fragments + ArtifactTable.fragments)
    check(UpcallBootstrap.publishToGlobals())
    PythonProxySource.install()
    PythonxAdapter.install(setOf("androidx.compose.ui.unit.Dp"))
    // The Python side: python/ and its uv environment (macOS and Linux layout).
    Python3.exec(
        """
        import sys, glob
        sys.path[0:0] = ["python"] + glob.glob("python/.venv/lib/python3*/site-packages")
        import main
        """.trimIndent(),
    )

    application {
        Window(onCloseRequest = ::exitApplication, title = "pythonx-compose") {
            PythonAppView(module = "pythonx.compose.runtime", attribute = "app_root")
        }
    }
}
./gradlew runDesktop

The relative paths are read from the directory runDesktop starts in, the project directory. The Gradle plugin stages CPython and sets PYTHONHOME for the run, so there is nothing to install for the interpreter. Redeclaring App with @app replaces the screen, and main.App.messages.setValue(...) changes the text, as in the notebook.

상대 경로는 runDesktop 이 시작하는 디렉터리, 즉 프로젝트 디렉터리 기준입니다. Gradle 플러그인이 CPython 을 준비하고 실행에 PYTHONHOME 을 설정하므로 인터프리터는 따로 설치할 것이 없습니다. 노트북에서처럼 @app 으로 App 을 다시 선언하면 화면이 바뀌고, main.App.messages.setValue(...) 는 글자를 바꿉니다.
